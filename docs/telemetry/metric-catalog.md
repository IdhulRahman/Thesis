## 2. Fundamental Measurement Principles & Semantic Guardrails

> [!IMPORTANT]
> In accordance with 3GPP TS 38.314, TS 28.552, and TS 23.288, physical telemetry must strictly observe the following principles:
> 1. **Sender Offered Load vs. Receiver Goodput:** `e2e_slice1_tput_mbps` measures client-side UDP offered rate generated by `iperf3 -u` on VM-5, not receiver-side arrival goodput at EXT-DN.
> 2. **Proxy Alokasi Grant PUSCH vs. Integrated Cell Usage:** `ran_prb_cell1` is formally defined as **“proxy alokasi grant PUSCH per UE dari log scheduler OAI”** ($\frac{NPRB}{106} \times 100\%$, where the denominator 106 aligns with 3GPP TS 38.104 Table 5.3.2-1 for 40 MHz SCS 30 kHz). Standard measurement of PUSCH PRB usage in 3GPP TS 38.314 (v17.2.0) §4.2.1.7.2 (defined in Table 4.2.1.7.2-1) operates in the time–frequency domain and integrates resource blocks over symbols ($RB \times \text{symbol}$). Consequently, an instantaneous grant peak ($N_{\text{PRB}} = 106$) indicates full instantaneous scheduling grant per TTI, distinct from continuous integrated cell utilization across the entire measurement interval.
> 3. **3GPP NWDAF Scope & Upstream Limitations:** Standard 3GPP NWDAF AnLF services in this testbed provide `UE_COMMUNICATION` analytics. Upstream OAI NWDAF v2.1.0 exhibits two distinct limitations: (a) Slice Load Level (`LOAD_LEVEL_INFORMATION` / `NSI_LOAD_LEVEL` per TS 23.288 §6.3) is unimplemented in the engine (endpoints return HTTP 404), causing standard `nwdaf_load_*` to emit strict `NaN`; (b) `relativeRatio` in `network_performance.go` is an uncalculated stub (`//TODO`) for the control-plane `SESS_SUCC_RATIO` event (TS 29.520 §5.1.6.3.10), which is separate from slice load.
> 4. **Host OAM Decoupling & Role Separation:** Linux kernel queue backlogs (`upf_backlog_bytes_*`) and packet drops (`upf_drops_*`) are authentic host/kernel-level OAM measurements. While 3GPP TS 23.288 defines OAM as a valid data source for NWDAF, these specific Linux qdisc counters are extracted directly from the host and are not provided through the AnLF service in this deployment. Similarly, `estimated_load_*` is calculated locally by `telemetry_collector.py` from UPF interface throughput; it is classified as a derived OAM proxy (Tier-2 Validation) and kept strictly separate from native NWDAF features (Tier-1).
> 5. **Duration Semantics:** `nwdaf_comm_duration_sec` represents upstream OAI cumulative report window aggregation, functioning as an event accumulation counter rather than an exact physical session elapsed time.
> 6. **Missing Value & Staleness Integrity:** Unsupported or unmeasured metrics emit strict **`NaN`** values, avoiding artificial synthetic defaults. Adapters hold the last valid parsed values during active transmissions and decay to `NaN` when unparsed formats occur or when staleness thresholds (e.g., 3.5 s) expire.
> 7. **Operator Label vs Automated Claims:** Scenario, domain, and component annotations (`event_*`) represent operator-designated experimental labels for the active recording session, not automated system assertions.

## 3. Telemetry Classification by Metric Type

The 40 columns of the experimental dataset are structured into six functional categories based on source domain and operational role:
1. **Session Metadata & Scrape Health** (Cols 1–5): Timing synchronization, run identification, and Prometheus scrape monitoring.
2. **End-to-End (E2E) Metrics (Service KPIs)** (Cols 6–12): User-perceived latency, offered throughput, packet loss, and canary probe freshness.
3. **3GPP NWDAF Metrics** (Cols 13–20): Standard 3GPP AnLF communication analytics and standard slice load queries.
4. **Real OAM & Host-Derived Telemetry** (Cols 21–26): Interface-derived throughput proxies and Linux kernel user-plane queue/drop counters.
5. **RAN Metrics** (Cols 27–34): Radio Access Network MAC scheduler grant allocation, modulation, BLER, and channel quality.
6. **rApp Targets & Ground-Truth Labels** (Cols 35–40): Non-RT RIC bottleneck inference targets and operator scenario annotations.

#### Technical Details & Semantics:
* **Native AnLF Ingestion Pipeline:** Sourced from `components/oai-nwdaf-engine/internal/engine/ue_communication.go`. UPF generates periodic PFCP Session Usage Reports (URR msg 56) every 30 seconds to SMF, which exposes them to `oai-nwdaf-sbi` and stores them in MongoDB `testing.smf`. * **Cumulative Duration Semantics:** Upstream OAI sums report window durations (`totalDuration += report.Duration`), causing `nwdaf_comm_duration_sec` to scale monotonically with the number of historical reports. This belongs to the `NETWORK_PERFORMANCE` (`SESS_SUCC_RATIO`) event (TS 29.520 §5.1.6.3.10), representing PDU session establishment success ratio, and is completely distinct from slice load.

#### Technical Details & Semantics:
* **Interface Throughput Proxy Formulation (`estimated_load_*`):** Computed locally in `telemetry_collector.py` (lines 594–603) from `upf_interface_tx_mbps` (ingested from `/proc/net/dev` on VM-3):
  $$\text{estimated\_load\_embb} = \min\left(100.0, \max\left(0.0, \frac{\text{upf\_interface\_tx\_mbps}}{C_{\text{norm, eMBB}}} \times 100.0\right)\right)$$
  Where $C_{\text{norm, eMBB}} = 25.0\text{ Mbps}$ and $C_{\text{norm, URLLC}} = 5.0\text{ Mbps}$ are the normalization reference divisor constants configured in the collector calculation. Idle traffic ($0\text{ Mbps}$) maps strictly to $0.0\%$. This metric provides local host-level visibility of UPF interface throughput relative to the reference capacity baseline; it is not a native NWDAF AnLF output.
* **Linux Netlink & Socket Buffer Mechanics:** Extracted via `iproute2` sending `RTM_GETQDISC` netlink queries to `net/sched/sch_api.c`. The kernel populates `qstats.backlog`, which sums the length (`skb->len`) of all `struct sk_buff` packets enqueued in the egress queue discipline. Under normal conditions (S1, S2), $B_{\text{backlog}} = 0$. Under Core rate-limiting or buffer constriction (S6, S9), backlogs build up significantly.
* **Monotonic Derivative Counter Tracking (`CounterTracker` v9):** In compliance with 3GPP TS 32.401 §5.4.1.5, drop rates are derived using `time.monotonic()`. Initial readings enter `INITIAL_BASELINE` ($t=0 \rightarrow \text{NaN}$) to prevent spurious derivative spikes. Counter wraparounds or container restarts trigger `COUNTER_DECREASE_REBASELINED`, resetting baseline state cleanly.
* **Core Slice Isolation at Egress Qdisc:** In analyzed dual-slice runs, `upf_backlog_bytes_urllc` and `upf_drops_urllc` remain strictly at `0`. This confirms that under the tested disturbance configurations and at this specific measurement point (Linux qdisc on UPF-2 `eth0`), no queue accumulation or packet drops were observed on the URLLC UPF egress queue, supporting the absence of queue cross-bleed at the qdisc layer for the analyzed runs (without generalizing to all potential forms of end-to-end slice contention).

#### Technical Details & Semantics:
* **Scheduler Grant Proxy vs Integrated Cell Load:** Extracted from `sched_pusch->rbSize` in `openair2/LAYER2/NR_MAC_gNB/gNB_scheduler_ulsch_default_policies.c`. Represents instantaneous grant allocation per TTI reporting instant ($N_{\text{PRB}} \in [0, 106]$ for 40 MHz SCS 30 kHz). It is formally documented as a **grant allocation proxy**, distinct from 3GPP TS 38.314 (v17.2.0) §4.2.1.7.2 continuous time–frequency cell PRB usage ($RB \times \text{symbol}$).
* **OAI BLER Formulation:** In the OAI gNB MAC implementation (`update_bler_stats()` in `openair2/LAYER2/NR_MAC_gNB/gNB_scheduler_primitives.c`), BLER is calculated as the ratio of initial retransmissions (first round retransmissions) to initial transmissions over an evaluation window, filtered via an exponentially weighted moving average (EWMA). It does not represent an unweighted cumulative average of all CRC failures across all HARQ retransmission rounds.
* **Dynamic Link Adaptation (DLA) & MCS Table Semantics:** `ran_mcs` reflects the UL-SCH MCS table active in the OAI gNB configuration. Under the deployed standard 64QAM table (3GPP TS 38.214 Table 6.1.4.1-1 / Table 5.1.3.1-1), baseline clean RF operates at the maximum non-reserved index of MCS 28, corresponding to modulation order $Q_m = 6$ (64QAM) with target code rate $948/1024$ and spectral efficiency $5.5547$. (Note: under Table 2 supporting 256QAM, index 28 is Reserved, so 256QAM uses indices up to 27). When radio link quality degrades (e.g., under RF attenuation), DLA dynamically steps down the MCS index to lower-order modulation (e.g., 16QAM or QPSK) to maintain block error rate targets.
* **Dual Causes of NaN in RAN Telemetry:** In `ran_adapter.py`, RAN metrics emit `NaN` under two distinct operational conditions:
  1. *Unparsed or Absent Fields in Specific Log Formats:* When gNB MAC logs emit the fallback NPRB format (lines 119–129), NPRB is parsed while BLER, MCS, SNR, and RSSI are immediately cleared to `None` (emitting `NaN`) because those specific channel statistics are absent from that log line pattern.
  2. *Stale Observations:* During active transmissions, the adapter holds the last valid parsed values across sub-second reporting gaps, decaying to `NaN` when no new radio log updates arrive for $\ge 3.5\text{ seconds}$ (`STALE_THRESHOLD_SEC`).
* **Multi-UE & Cell-2 Dynamic:** The testbed spawner (`scripts/spawn_multi_ue.sh`) maps Slice 1 (eMBB) to DU-1/Cell-1 (Port `4043`) and Slice 2 (URLLC) to DU-2/Cell-2 (Port `4044`). In dual-UE deployments where UE-2 is active, Cell-2 scheduler logs report active PRB and radio metrics for UE-2. If a specific experiment run is configured as single-UE (only UE-1 active on Slice 1), Cell-2 scheduler logs contain no scheduled transmissions and its metrics decay to `NaN`.

## 4. Dataset Integrity & Empirical Disturbance Registry

### 4.1 Clean Elimination of Hardcoded Synthetic Fallbacks
In earlier pilot revisions, when gNB MAC logs lacked explicit scheduling records, fallback heuristics provisioned synthetic defaults (`snr=25.0, rssi=-42.0`). In the current production baseline (commit `fd6b1f3`), all synthetic fallbacks have been completely removed:
* When radio transport blocks are unallocated, log fields are absent, or gNB logs lack active scheduling records for $\ge 3.5\text{ s}$, radio metrics decay strictly to **`NaN`**.
* When the UPF container stops or probes time out ($\ge 3.5\text{ s}$), core queue backlogs, drop rates, and interface load proxies decay strictly to **`NaN`**.
* When the NWDAF slice load endpoint is unsupported upstream, the metric emits strict **`NaN`**.
* This strict absence policy guarantees zero synthetic imputation bias during machine learning training.
