# Telemetry Metric Catalog & CSV Dataset Specification

**Authoritative Specification:** Single Source of Truth for the 37-Column Dataset  
**Standard Mappings:** 3GPP TS 23.288, TS 29.520, TS 28.552, TS 38.314, IETF RFC 3550  
**Target Environment:** VM-6 Monitoring Host (`telemetry_collector.py` & `record_dual_stream.py`)  
**Data Logging Cadence:** Nominal 1.000 Hz (1 sample per second) synchronized via Monotonic Clock

## 2. Fundamental Measurement Principles & Semantic Guardrails

> [!IMPORTANT]
> **Measurement Semantics & Scientific Guardrails:**
> In accordance with 3GPP TS 38.314, TS 28.552, and TS 23.288, physical telemetry must strictly distinguish between:
> 1. **Sender Offered Load vs. Receiver Goodput:** `e2e_slice1_tput_mbps` measures client-side UDP offered rate generated by `iperf3 -u` on VM-5, not receiver-side arrival goodput at EXT-DN.
> 2. **Instantaneous Allocation vs. Integrated Cell Usage:** `ran_prb_cell1` measures the instantaneous MAC slot allocation ($NPRB / 106$) of the active UE from the latest DU scheduler log line, distinct from TS 38.314 time-integrated cell PRB usage.
> 3. **Raw Telemetry vs. Empirical Transformation:** `estimated_load_embb` is a research utilization proxy derived from UPF interface egress throughput, strictly decoupled from 3GPP NWDAF metrics.
> 4. **Standard 3GPP NWDAF Ingestion:** `nwdaf_comm_*` metrics represent standard 3GPP user-plane communication telemetry exposed over NBI `Nnwdaf_AnalyticsInfo` (`UE_COMMUNICATION`).
> 5. **Duration Semantics:** `nwdaf_comm_duration_sec` represents upstream OAI cumulative report window aggregation, functioning as an event accumulation counter rather than an exact physical session elapsed time.
> 6. **Missing Value Integrity:** Unsupported or unmeasured metrics (such as `nwdaf_load_embb` or unmeasured UDP transit jitter) emit strict **`NaN`** values, avoiding artificial synthetic defaults.

## 4. Deep Technical Analysis & Semantics

### 4.1 Distinction: CSV Columns vs. Prometheus Gauge Identifiers
A common point of confusion is equating the number of columns in the CSV with the number of raw Prometheus metric names. 
* The **CSV dataset contains exactly 37 columns** representing a flattened, single-row feature vector per second.
* In Prometheus, several metrics are partitioned across labels:
  * `estimated_slice_load_level{snssai="01000001"}` and `estimated_slice_load_level{snssai="de00007b"}` originate from a single Prometheus metric family with distinct slice labels.
  * `ran_cell_prb_utilization{cell_id="1"}` and `ran_cell_prb_utilization{cell_id="2"}` originate from a single metric family with distinct cell labels.
* The logger (`record_dual_stream.py`) explicitly evaluates metric labels to populate discrete CSV columns (`ran_prb_cell1`, `ran_prb_cell2`).

### 4.2 Semantic Limitation of `nwdaf_comm_duration_sec`
In the upstream OAI NWDAF engine (`components/oai-nwdaf-engine/internal/engine/ue_communication.go`):
```go
for _, report := range qosMonList {
    totalDuration += report.Duration
    totalUlVol += report.UlVolume
    totalDlVol += report.DlVolume
}
```
When UPF generates periodic usage reports every 30 seconds, `report.Duration` contains the elapsed duration of that report window. By calculating `totalDuration += report.Duration`, the engine sums overlapping intervals across all historical reports in the requested window, yielding monotonically inflated duration totals (e.g., >8000s). In this research dataset, `nwdaf_comm_duration_sec` is utilized as a **monotonic URR event accumulation counter**, while physical session elapsed time is strictly measured via `elapsed_sec`.

### 4.3 Clean Elimination of Hardcoded Synthetic Fallbacks
In earlier pilot revisions, when gNB MAC logs lacked explicit scheduling records, fallback heuristics provisioned synthetic defaults (`snr=25.0, rssi=-42.0`). In the current production baseline (commit `fd6b1f3`), all synthetic fallbacks have been completely removed. If a transport block is unallocated or a log pattern cannot be extracted, the metric emits **`NaN`**, guaranteeing zero artificial bias in downstream machine learning training.

### 4.4 Estimated Slice Load Formulation
The estimated load columns (`estimated_load_embb` and `estimated_load_urllc`) provide an empirical research proxy of interface bandwidth consumption:
$$\text{estimated\_load\_embb} = \min\left(100.0, \max\left(5.0, \frac{\text{upf\_interface\_tx\_mbps}}{C_{\text{eMBB}}} \times 100.0\right)\right)$$
Where $C_{\text{eMBB}} = 25.0\text{ Mbps}$ (calibrated interface capacity) and $C_{\text{URLLC}} = 5.0\text{ Mbps}$. The minimum floor of $5.0\%$ reflects baseline quiescent signaling overhead. This value is strictly documented as an empirical research estimate, completely decoupled from native 3GPP NWDAF analytics.
