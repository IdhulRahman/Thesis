**Authoritative Specification:** Single Source of Truth for the 40-Column Dataset  
**Standard Mappings:** 3GPP TS 23.288, TS 29.520, TS 28.552, TS 38.314, IETF RFC 3550

## 2. Fundamental Measurement Principles & Semantic Guardrails

> [!IMPORTANT]
> In accordance with 3GPP TS 38.314, TS 28.552, and TS 23.288, physical telemetry must strictly distinguish between:
> 1. **Sender Offered Load vs. Receiver Goodput:** `e2e_slice1_tput_mbps` measures client-side UDP offered rate generated by `iperf3 -u` on VM-5, not receiver-side arrival goodput at EXT-DN.
> 2. **Proxy Alokasi Grant PUSCH vs. Integrated Cell Usage:** `ran_prb_cell1` is formally defined as **“proxy alokasi grant PUSCH per UE dari log scheduler OAI”** ($\frac{NPRB}{106} \times 100\%$, where the denominator 106 aligns with 3GPP TS 38.104 Table 5.3.2-1 for 40 MHz SCS 30 kHz). As agreed with the evaluator, sample mean and max on CSV serve as valid proxy statistics. This is distinct from 3GPP TS 38.314 time–frequency integrated cell PRB usage ($RB \times symbol$).
> 3. **Raw Telemetry vs. Empirical Transformation:** `estimated_load_embb` is a research utilization proxy derived from UPF interface egress throughput, strictly decoupled from 3GPP NWDAF metrics.
> 4. **Standard 3GPP NWDAF Ingestion:** `nwdaf_comm_*` metrics represent standard 3GPP user-plane communication telemetry exposed over NBI `Nnwdaf_AnalyticsInfo` (`UE_COMMUNICATION`).
> 5. **Duration Semantics:** `nwdaf_comm_duration_sec` represents upstream OAI cumulative report window aggregation, functioning as an event accumulation counter rather than an exact physical session elapsed time.
> 6. **Missing Value Integrity:** Unsupported or unmeasured metrics (such as `nwdaf_load_embb` or unmeasured UDP transit jitter) emit strict **`NaN`** values, avoiding artificial synthetic defaults.
> 7. **Operator Label vs Automated Claims:** Scenario, domain, and component annotations (`event_*`) represent operator-designated experimental labels for the active recording session, not automated system assertions.

## 4. Deep Technical Analysis & Semantics

### 4.1 Distinction: CSV Columns vs. Prometheus Gauge Identifiers
A common point of confusion is equating the number of columns in the CSV with the number of raw Prometheus metric names. 
* The **CSV dataset contains exactly 40 columns** representing a flattened, single-row feature vector per second.
* In Prometheus, several metrics are partitioned across labels:
  * `estimated_slice_load_level{snssai="01000001"}` and `estimated_slice_load_level{snssai="de00007b"}` originate from a single Prometheus metric family with distinct slice labels.
  * `ran_cell_prb_utilization{cell_id="1"}` and `ran_cell_prb_utilization{cell_id="2"}` originate from a single metric family with distinct cell labels.
* The recorder (`record_experiment.py`) explicitly evaluates metric labels to populate discrete CSV columns (`ran_prb_cell1`, `ran_prb_cell2`).

### 4.2 Semantic Limitation of `nwdaf_comm_duration_sec`
In the upstream OAI NWDAF engine (`components/oai-nwdaf-engine/internal/engine/ue_communication.go`):
```go
for _, report := range qosMonList {
    totalDuration += report.Duration
    totalUlVol += report.UlVolume
    totalDlVol += report.DlVolume
}
```
When UPF generates periodic usage reports every 30 seconds, `report.Duration` contains the elapsed duration of that report window. By calculating `totalDuration += report.Duration`, the engine sums overlapping intervals across all historical reports in the requested window, yielding monotonically inflated duration totals (e.g., >8000s). In this research dataset, `nwdaf_comm_duration_sec` is utilized as a **monotonic URR event accumulation counter**, while physical session elapsed time is strictly measured via `elapsed_sec`.

### 4.3 Clean Elimination of Hardcoded Synthetic Fallbacks
In earlier pilot revisions, when gNB MAC logs lacked explicit scheduling records, fallback heuristics provisioned synthetic defaults (`snr=25.0, rssi=-42.0`). In the current production baseline (commit `fd6b1f3`), all synthetic fallbacks have been completely removed. If a transport block is unallocated or a log pattern cannot be extracted, the metric emits **`NaN`**, guaranteeing zero artificial bias in downstream machine learning training.

### 4.4 Estimated Slice Load Formulation
The estimated load columns (`estimated_load_embb` and `estimated_load_urllc`) provide an empirical research proxy of interface bandwidth consumption:
$$\text{estimated\_load\_embb} = \min\left(100.0, \max\left(0.0, \frac{\text{upf\_interface\_tx\_mbps}}{C_{\text{eMBB}}} \times 100.0\right)\right)$$
Where $C_{\text{eMBB}} = 25.0\text{ Mbps}$ (calibrated interface capacity) and $C_{\text{URLLC}} = 5.0\text{ Mbps}$. Quiescent idle traffic ($0\text{ Mbps}$) maps strictly to $0.0\%$, eliminating synthetic minimum floors. This value is strictly documented as an empirical research estimate, completely decoupled from native 3GPP NWDAF analytics.

#### 4.5.1 Unused RAN Capabilities in OAI Log Pipeline
The OAI DU scheduler logs emit additional authentic radio metrics that are ingested by `ran_adapter.py` and exported to Prometheus, but excluded from the 40-column CSV dataset to avoid collinearity:
1. **`ran_cell_rssi_dbm` (`RSSI` in log):** Total received RF signal power in dBm. Highly collinear with `ran_snr` ($r > 0.98$ in AWGN RFsim), hence `ran_snr` is retained as the primary RF indicator.
2. **`ran_cell_ulsch_errors` (`ulsch_errors` in log):** Cumulative counter of permanently dropped transport blocks failing CRC after exhausting all 4 HARQ rounds. Excluded from CSV because `ran_bler` provides a normalized, continuous rate metric.
3. **`ulsch_DTX` (Discontinuous Transmission):** Triggered when PUSCH grant energy falls below detection threshold (`pusch_dtx_threshold`). Serves as an empirical precursor to Radio Link Failure (RLF).
4. **`goodput UL` (MAC Goodput):** Layer-2 throughput strictly excluding MAC retransmissions, computed per UE context in OAI.

#### 4.5.2 Cross-Scenario Dual-Cell Dynamic (Cell-1 vs. Cell-2)
* **Single-Cell Scenarios (S1, S2, S3, S6, S9):** Only DU-1 (Cell-1) serves active UE traffic. DU-2 (Cell-2) is running as baseline control without attached UEs. Consequently, `ran_*_cell2` metrics consistently emit **`NaN`**, honestly reflecting the physical reality of an unallocated radio cell.
* **Handover Scenarios (S10_A, S10_B):** The UE transitions connection from Cell-1 to Cell-2 via A3 event trigger. During handover, `ran_prb_cell1` drops towards 0 / NaN while `ran_prb_cell2` transitions from `NaN` to active grant (~100%), demonstrating true spatial-domain traffic steering.

#### 4.6.1 Linux Kernel Qdisc and Socket Buffer Mechanics (`sk_buff` / Netlink)
The Core user-plane metrics are extracted directly from the Linux host networking subsystem inside each UPF container:
1. **Netlink Net Device Statistics:** The Linux kernel manages packet queues via queuing disciplines (qdiscs) attached to network devices. When `core_adapter.py` runs `tc -j -s qdisc show dev eth0`, `iproute2` sends an `RTM_GETQDISC` request via AF_NETLINK socket to `net/sched/sch_api.c`.
2. **Backlog Memory Tracking:** The kernel populates `qstats.backlog`, which sums the `skb->len` of all socket buffers (`struct sk_buff`) currently enqueued in the active queue discipline. Under normal operation (S1, S2, CLEAR_FAULT), packets are transmitted immediately ($B_{\text{backlog}} = 0$). Under artificial queue constriction (S6, S9, S10_A) via Token Bucket Filter (`tbf`) or Netem delay/loss queues, buffer buildup occurs, climbing to approximately 303,700 Bytes (~300 KB).
3. **Packet Drop Accounting:** If the queue buffer fills or Netem drop rules trigger, the kernel increments `qstats.drops` (in `sch_generic.c` or specific qdisc drop paths). The adapter computes the derivative drop rate, reaching up to ~769 drops/s in S6 and ~2,105 drops/s in S9 (joint overload).

#### 4.6.2 Monotonic Derivative Counter Tracking (`CounterTracker` v9)
In compliance with 3GPP TS 32.401 §5.4.1.5 and TS 32.435 §4.2.2 measurement rules, `core_adapter.py` v9 utilizes a specialized `CounterTracker` class to calculate derivatives without wall-clock distortion:
* **Monotonic Interval Timing:** Intervals are measured strictly via `time.monotonic()`, preventing distortions from NTP clock adjustments, leap seconds, or daylight saving time.
* **Warm-Up State (`INITIAL_BASELINE`):** The very first reading establishes the baseline without computing a rate ($t=0 \rightarrow \text{rate} = \text{NaN}$), preventing division-by-zero or arbitrary spike anomalies.
* **Counter Wraparound and Reset Detection:** If a container restarts or interface reset occurs such that current count $C_t < C_{t-1}$, the tracker triggers `COUNTER_DECREASE_REBASELINED`, resetting baseline state without emitting spurious negative derivatives.
* **Staleness Guard:** If the sampling interval exceeds a maximum staleness threshold ($\Delta t > 10\text{ s}$), `STALE_BASELINE_REINITIALIZED` drops the stale delta to avoid averaging over an extended outage.

#### 4.6.3 Slice Isolation & Cross-Scenario Dynamics (eMBB vs. URLLC)
The 5G Core deployment enforces physical network slice separation across isolated Docker containers:
* **eMBB Slice (`01000001` on `oai-upf-slice1`):** Serves high-bandwidth video/data streams. In S1 (Normal Light, ~10 Mbps), load is ~41.2%; in S2 (Normal High, ~20 Mbps), load is ~82.3%; in S3 (RAN Overload), load saturates at 100.0%. In S6 and S9, Core bottlenecking induces ~300 KB queue backlogs and heavy packet drops, dropping egress throughput to ~48% (~12 Mbps).
* **URLLC Slice (`de00007b` on `oai-upf-slice2`):** Dedicated low-latency slice handling control and periodic keepalive traffic. In all scenarios, throughput remains at ~0.02 Mbps (`estimated_load_urllc` mean ~0.39%, max 0.60%), with strictly 0 bytes backlog and 0 drops, demonstrating pristine slice isolation where eMBB core congestion does not bleed into the URLLC user plane.
* **Research Demarcation for Thesis:** The thesis must explicitly highlight that while `upf_backlog_bytes` and `upf_drops` are authentic physical Linux kernel measurements, `estimated_load` is an empirical proxy calculated from egress interface throughput normalized to SLA bandwidth ($C_{\text{slice}}$), providing actionable user-plane telemetry for the Non-RT RIC rApp when standard 3GPP NWDAF slice load analytics are unavailable in open-source implementations.
