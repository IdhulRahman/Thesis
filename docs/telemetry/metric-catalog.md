## 2. Fundamental Measurement Principles & Semantic Guardrails

> [!IMPORTANT]
> In accordance with 3GPP TS 38.314, TS 28.552, and TS 23.288, physical telemetry must strictly observe the following principles:
> 1. **Sender Offered Load vs. Receiver Goodput:** `e2e_slice1_tput_mbps` measures client-side UDP offered rate generated by `iperf3 -u` on VM-5, not receiver-side arrival goodput at EXT-DN.
> 2. **Proxy Alokasi Grant PUSCH vs. Integrated Cell Usage:** `ran_prb_cell1` is formally defined as **“proxy alokasi grant PUSCH per UE dari log scheduler OAI”** ($\frac{NPRB}{106} \times 100\%$, where the denominator 106 aligns with 3GPP TS 38.104 Table 5.3.2-1 for 40 MHz SCS 30 kHz). This is distinct from 3GPP TS 38.314 time–frequency integrated continuous cell PRB usage ($RB \times \text{symbol}$).
> 3. **NWDAF Domain & Version Bridge:** Standard 3GPP NWDAF AnLF services provide `UE_COMMUNICATION` analytics. Because upstream OAI NWDAF v2.1.0 lacks complete slice load level analytics (`relativeRatio //TODO`), standard `nwdaf_load_*` emits strict `NaN`, while `estimated_load_*` serves as an empirical capacity-normalized throughput ratio proxy to bridge this upstream implementation gap.
> 4. **Real OAM Host Decoupling:** Linux kernel queue backlogs (`upf_backlog_bytes_*`) and packet drops (`upf_drops_*`) are authentic host/kernel-level OAM measurements. They do not exist in 3GPP NWDAF specifications and serve strictly as independent ground-truth verification and core congestion indicators.
> 5. **Duration Semantics:** `nwdaf_comm_duration_sec` represents upstream OAI cumulative report window aggregation, functioning as an event accumulation counter rather than an exact physical session elapsed time.
> 6. **Missing Value Integrity:** Unsupported or unmeasured metrics emit strict **`NaN`** values, avoiding artificial synthetic defaults (such as earlier fallback heuristics).
> 7. **Operator Label vs Automated Claims:** Scenario, domain, and component annotations (`event_*`) represent operator-designated experimental labels for the active recording session, not automated system assertions.

## 3. Telemetry Classification by Metric Type

The 40 columns of the experimental dataset are structured into four primary functional categories, supported by session metadata and experimental labels:
1. **End-to-End (E2E) Metrics (Service KPIs)**: Application-layer performance, delay, packet loss, and probe freshness.
2. **NWDAF Metrics**: 3GPP standard AnLF user-plane analytics and capacity-normalized slice load metrics bridging upstream engine limitations.
3. **Real OAM Metrics**: Host and Linux kernel-level user-plane queuing and drop telemetry absent from NWDAF specifications.
4. **RAN Metrics**: Radio Access Network physical and MAC layer scheduling telemetry.
5. **Session Metadata & Target Labels**: Timing synchronization, rApp inference classifications, and ground-truth scenario annotations.

### 3.2 NWDAF Metrics (3GPP Analytics & Slice Load Bridge)

This category encompasses 3GPP TS 23.288 / TS 29.520 Analytics Logical Function (AnLF) user-plane metrics and slice load analytics. It includes:
1. **Native NWDAF AnLF Metrics (`UE_COMMUNICATION`):** Ingested via Kong NBI Gateway (`:8080`) from the upstream OAI NWDAF engine, calculated from UPF Usage Reports (URR).
2. **Slice Load Level Analytics & Bridge:** 3GPP TS 23.288 §6.3 defines `LOAD_LEVEL_INFORMATION` for network slices. Because the deployed upstream OAI NWDAF v2.1.0 engine leaves this unimplemented (`relativeRatio //TODO` and unregistered HTTP 404 endpoints), `nwdaf_load_*` strictly emits `NaN`. To provide actionable user-plane load visibility for the Non-RT RIC rApp without violating provenance, `estimated_load_*` provides an empirical capacity-normalized throughput ratio proxy, bridging this upstream software limitation.

| **14**| `nwdaf_load_urllc` | `nwdaf_slice_load_level{snssai="de00007b"}` | VM-3 NWDAF :8080 | 3GPP NBI | Float (%) | Standard 3GPP TS 23.288 Slice Load Level for URLLC | Strictly emits `NaN` (unsupported upstream) | NWDAF Standard Load |

| **19**| `nwdaf_comm_freshness` | `nwdaf_comm_freshness` | VM-3 NWDAF :8080 | VM-6 Collector | Boolean (0/1) | Freshness indicator: `1` if source URR volume changed $\le 45\text{ s}$, else `0` | Drops to `0` when URR idle | NWDAF Data Freshness |

| **21**| `estimated_load_embb` | `estimated_slice_load_level{snssai="01000001"}` | VM-3 UPF-1 | `core_adapter.py` | Float (%) | $\min\left(100.0, \max\left(0.0, \frac{\text{Tx}_{\text{mbps}}}{25.0} \times 100.0\right)\right)$ | Decays to `NaN` after 3.5s | NWDAF Load Bridge |
| **22**| `estimated_load_urllc`| `estimated_slice_load_level{snssai="de00007b"}` | VM-3 UPF-2 | `core_adapter.py` | Float (%) | $\min\left(100.0, \max\left(0.0, \frac{\text{Tx}_{\text{mbps}}}{5.0} \times 100.0\right)\right)$ | Decays to `NaN` after 3.5s | NWDAF Load Bridge |

#### Technical Details & Semantics:
* **Native AnLF Ingestion Pipeline:** Sourced from `components/oai-nwdaf-engine/internal/engine/ue_communication.go`. UPF generates periodic PFCP Session Usage Reports (URR msg 56) every 30 seconds to SMF, which exposes them to `oai-nwdaf-sbi` and stores them in MongoDB `testing.smf`. The engine aggregates cumulative UL/DL volume and calculates volume standard deviation via `math.Sqrt(ulVolVariance)`.
* **Cumulative Duration Semantics:** Upstream OAI sums report window durations (`totalDuration += report.Duration`), causing `nwdaf_comm_duration_sec` to scale monotonically with the number of historical reports. In this dataset, it serves as a **monotonic URR event accumulation counter**, while true experiment elapsed time is tracked by `elapsed_sec`.
* **Estimated Slice Load Formulation:**
  $$\text{estimated\_load\_embb} = \min\left(100.0, \max\left(0.0, \frac{\text{upf\_interface\_tx\_mbps}}{C_{\text{eMBB}}} \times 100.0\right)\right)$$
  Where $C_{\text{eMBB}} = 25.0\text{ Mbps}$ and $C_{\text{URLLC}} = 5.0\text{ Mbps}$. Idle traffic ($0\text{ Mbps}$) maps strictly to $0.0\%$. This metric bridges the upstream NWDAF version gap and is formally designated as an empirical throughput ratio proxy.

### 3.3 Real OAM Metrics (Kernel Queue & Host Observability)

Real OAM metrics represent pure host infrastructure and Linux kernel-level networking telemetry extracted from the UPF container execution environment. These metrics **do not exist in 3GPP NWDAF documentation or NBI standards**. Sourced directly from Linux kernel queuing disciplines (`tc qdisc`) via AF_NETLINK sockets, they provide independent ground-truth verification and core congestion indicators.

| Col | CSV Column Name | Prometheus Identifier | Source & Host | Ingestion Channel | Unit & Type | Extraction Logic & Mathematical Formulation | Missing / Stale Rule | OAM / Verification Role |
|:---:|---|---|---|---|---|---|---|---|
| **23**| `upf_backlog_bytes_embb`| `upf_queue_backlog_bytes{snssai="01000001"}`| VM-3 UPF-1 | `core_adapter.py` | Integer (Bytes) | Linux `tc -s qdisc show dev eth0` backlog bytes on UPF-1 container (`qstats.backlog`) | Decays to `NaN` after 3.5s | Host Kernel Queue Depth |
| **24**| `upf_backlog_bytes_urllc`| `upf_queue_backlog_bytes{snssai="de00007b"}`| VM-3 UPF-2 | `core_adapter.py` | Integer (Bytes) | Linux `tc -s qdisc show dev eth0` backlog bytes on UPF-2 container (`qstats.backlog`) | Decays to `NaN` after 3.5s | Host Kernel Queue Depth |
| **25**| `upf_drops_embb` | `upf_packet_drops{snssai="01000001"}` | VM-3 UPF-1 | `core_adapter.py` | Float (drops/s) | Derivative packet drop rate: $\Delta \text{drops} / \Delta t$ over interval on UPF-1 | Decays to `NaN` after 3.5s | Host Kernel Drop Rate |
| **26**| `upf_drops_urllc` | `upf_packet_drops{snssai="de00007b"}` | VM-3 UPF-2 | `core_adapter.py` | Float (drops/s) | Derivative packet drop rate: $\Delta \text{drops} / \Delta t$ over interval on UPF-2 | Decays to `NaN` after 3.5s | Host Kernel Drop Rate |

#### Technical Details & Semantics:
* **Linux Netlink & Socket Buffer Mechanics:** Extracted via `iproute2` sending `RTM_GETQDISC` netlink queries to `net/sched/sch_api.c`. The kernel populates `qstats.backlog`, which sums the length (`skb->len`) of all `struct sk_buff` packets enqueued in the egress queue discipline. Under normal conditions (S1, S2), $B_{\text{backlog}} = 0$. Under Core rate-limiting or buffer constriction (S6, S9), backlogs climb to $\approx 303\text{ KB}$.
* **Monotonic Derivative Counter Tracking (`CounterTracker` v9):** In compliance with 3GPP TS 32.401 §5.4.1.5, drop rates are derived using `time.monotonic()`. Initial readings enter `INITIAL_BASELINE` ($t=0 \rightarrow \text{NaN}$) to prevent spurious derivative spikes. Counter wraparounds or container restarts trigger `COUNTER_DECREASE_REBASELINED`, resetting baseline state cleanly.
* **Core Slice Isolation:** In all scenarios, `upf_backlog_bytes_urllc` and `upf_drops_urllc` remain strictly at `0`, proving that eMBB queue buffer saturation on `oai-upf-slice1` does not bleed into the isolated URLLC slice container (`oai-upf-slice2`).

## 4. Dataset Integrity & Absence Guardrails

### 4.1 Clean Elimination of Hardcoded Synthetic Fallbacks
In earlier pilot revisions, when gNB MAC logs lacked explicit scheduling records, fallback heuristics provisioned synthetic defaults (`snr=25.0, rssi=-42.0`). In the current production baseline (commit `fd6b1f3`), all synthetic fallbacks have been completely removed:
* When a radio transport block is unallocated or a gNB log pattern is absent, the metric emits strict **`NaN`**.
* When the UPF container stops or probes time out ($\ge 3.5\text{ s}$), core queue backlogs and drop rates decay strictly to **`NaN`**.
* When the NWDAF slice load endpoint is unsupported upstream, the metric emits strict **`NaN`**.
* This strict absence policy prevents artificial bias in downstream machine learning model training and fair baseline comparison.
